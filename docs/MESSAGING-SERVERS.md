## Limites et choix explicites

- Un alias Matrix ne contourne pas un espace sur invitation. Créer un code rend donc l’espace **public à l’adhésion** ; les salons ordinaires restent limités à ses membres et les salons privés restent sur invitation. Texte explicite dans l’UI. Pas d’expiration/révocation de codes dans cette passe ; un nouveau lancement peut créer un autre alias, les précédents restent utilisables.
- La réparation d’accès ouvre tous les enfants, y compris les anciens privés, après confirmation forte. Une ancienne version de salon peut refuser `restricted` ; l’erreur est affichée, aucune migration destructrice automatique.
- Les opérations de modération portant sur plusieurs salons ne sont pas atomiques dans Matrix : une permission insuffisante peut produire un résultat partiel signalé. Les rôles personnalisés/nommés ne sont pas inventés.
- Retirer un salon de l’espace et le quitter n’efface pas son historique pour ses autres membres. La confirmation le dit. Supprimer totalement un serveur reste masqué.
- L’annuaire masque les personnes sans salon commun ; l’identifiant exact reste utilisable. Les reçus dépendent des préférences du correspondant et des événements reçus, pas d’une preuve que la personne a réellement lu le texte.
- Pas de validation visuelle Mac, puisque le brief interdit tout lancement d’app Mac ; aucune revendication de fidélité pixel par pixel sur ces nouveaux états. Les captures prouvent le rendu iPhone de démo, pas le transport ou les interactions réelles. Le rendu markdown reste un sous-ensemble (pas de masquage interactif des spoilers).
